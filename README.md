# 搭桥 Hashi

一个基于 Web 的搭桥（Hashi）谜题游戏，原生 SVG 渲染，内置逻辑解题器。

## 在线体验

```bash
npm install
npm start
```

`npm start` 会等开发服务就绪后用默认浏览器打开 **http://127.0.0.1:5200/**。

> 也可以用 `npm run dev`，但不会自动打开浏览器。

## 游戏规则

- 在同行或同列的两个岛之间架直线桥，桥不能穿过其他岛
- 两岛之间最多两座桥，桥不能交叉
- 每个岛的数字等于与它相连的桥数
- 所有岛必须连成一个整体

## 操作

| 操作 | 说明 |
|------|------|
| 左键点两岛之间的线 | 切换 0 / 1 / 2 座桥 |
| 右键点线 | 清除桥 |
| 按住拖动 | 连续架桥 |
| 滚轮 / 中键拖拽 | 缩放 / 平移画布 |
| Z / Shift+Z / Y | 撤销 / 重做 |
| C / H / S / Esc | 检查 / 提示一格 / 显示解 / 清空 |
| R / L / P / M | 随机抽题 / 逻辑解题 / 暂停回放 / 音效开关 |
| 0 / + / - | 视图复位 / 放大 / 缩小 |

## 数据存放

运行 `npm start` / `npm run dev` 时，题库、进度和上次题目保存在项目内 `data/` 目录；静态部署时自动降级到浏览器 localStorage。

## 从图片导入题目

点工具栏的「图片导入」：

1. 选择一张题目截图（黑边圆点 + 数字的常见 Hashi 题面）。
2. 工具按暗色连通块自动找出所有圆点岛，并拟合出行列网格。
3. 圆内数字会用系统字体模板自动识别（1-8），高置信度的先自动填好；没读出/读错的点岛后按 `1`-`8` 补填，`Backspace` 清除，方向键换岛。原始数字仍显示在图上方便核对。
4. 点「保存到题库并载入」直接写入题库。自定义题不强制唯一解，可以先保存任意题面，之后再编辑或求解。

命令行同样可以识别并写入题库（与面板共用 `src/game/image-import.ts`）：

```bash
# 只识别、预览岛阵与数字（默认不写盘）
npm run import-image -- QQ_1794679015274.png

# 校验唯一解后写入 data/library.json
npm run import-image -- QQ_1794679015274.png --name "识图导入 · 15×15" --verify --append

# 人工修正数字：r3c5=4 表示第 3 行第 5 列的岛填 4（1 基）
npm run import-image -- QQ_1794679015274.png --map r3c5=4,r3c12=1 --append
```

| 参数 | 说明 |
|------|------|
| `--name 名称` / `--id ID` | 题库名称 / 指定 id（覆盖同 id 条目） |
| `--append` | 写入 `data/library.json`；不加只预览 |
| `--verify` | 唯一解校验（`--allow-multi` 可放宽，`--allow-none` 允许无解） |
| `--map 修正` | `r3c5=4` 改第 3 行第 5 列数字（0 清空） |
| `--min-conf N` | 自动填数字的最低置信度（默认 0.3） |
| `--max-nodes N` / `--out FILE` / `--json` | 搜索节点上限 / 题库文件 / 机器可读输出 |

数字识别依赖题图圆内是常见无衬线数字；字体太花或分辨率太低时用 `--map` 修正（预览会把低置信度候选列出来）。

月度大盘（本项目 `month.png` 为 40×50、600 个岛）也能直接识别：

```bash
npm run import-image -- month.png --dry-run        # 预览：40×50、600 个岛、数字全部读出
npm run import-image -- month.png --append --name "月度 · 40×50"
```

- 数字识别用的是与岛检测分离的高分辨率画布（最长边 2600px），大盘每格只有 30 多像素时
  也能把圆内数字读准；旧截图（`QQ_*.png` 等 15×15）识别结果不变。
- 圆心/半径会按拟合出的格线做规整，圆环描边断成圆弧的个别岛也不会把数字 ROI 裁歪。
- `npm run check` 只审计内置题；想看导入的大盘是否唯一解，用 `--verify`（600 个岛通常几节点
  就能判定，真正的瓶颈只在大规模乱序题面）。
- `--append` 在岛数 > 200 时默认把搜索节点上限压到 2 万，超时只告警、题面照常入库；
  需要更强校验时显式传 `--max-nodes`。

题面是稀疏的：没有数字的格子不参与绘制，棋盘留白按实际有岛的边界对齐。

## 自定义题目

工具栏「自定义」打开编辑器，尺寸 2×2 到 120×120，保存不要求唯一解。三种输入方式：

1. **点格子**：点击循环 空 → 1 → … → 8；键盘 `1`-`8` 填岛，`0` / `Backspace` 清空，方向键换格。
2. **文本导入**：按行粘贴，每行一格，`0` / `.` / 空格为空，`1`-`8` 为岛，然后点「文本导入」。
3. **图片导入**：直接走上面的图片识别流程，保存后同样进入题库。

「载入题板」会保存并载入；「保存到题库」只保存。题库列表里的自定义题带「编辑 / 删除」：编辑会把原题读回编辑器，再次保存时覆盖同一个 id；「生成网格」会清掉编辑态，开始一道新题。题面完全相同的条目会自动去重。

## 解谜器规则

逻辑推理（`src/game/rules.ts` 的 `propagate`）对每条候选桥维护 `{0,1,2}` 的取值域，反复执行：

1. **域上下界 / 唯一剩余边**：对每个岛计算「最小可凑桥数」和「最大可凑桥数」。数字超出范围 → 矛盾；数字等于最小值 / 最大值 → 所有边取各自最小 / 最大值；再逐边剔除「加上其他边的上下界也凑不出数字」的取值。唯一剩余边、强制 0/2、至少一座桥等都在这一条里统一处理。
2. **交叉封锁**：一条边如果已经确定必须为正（域里没有 0），所有与它交叉的垂直 / 水平候选边直接设为 0；两条交叉边都「必须为正」→ 矛盾。
3. **连通必经**：用「还可能为正」的候选边建图。图不连通 → 无解；图中的桥边（删掉就断开）必须为正。
4. **岛群割约束**（标准「岛群计数」定式）：取任意一组岛 S（真子集，只枚举候选边连起来的岛群），记线索和 D、群内桥数 I、出群桥数 X，则 `D = 2I + X`：
   - **连通性**：S 必须至少有一条桥连出去 → `X ≥ 1`（否则 S 会被孤立成独立岛群）；
   - **奇偶性**：`X = D - 2I` → X 与 D 同奇偶；
   - **上下界**：I、X 各自不超过候选边的取值上限，联立得到 X 的可行区间，再逐边检查「这条边取 v 后，其它边还能不能凑出合法区间和奇偶」。
   - 常见特例都在这一条里：两个相邻的「1」不能互连（否则两岛孤立成一对）、角落 3 / 边上 5 每个方向至少一座桥、某片岛群出群桥数被凑满等。
   - 岛群枚举按岛数分级限规模（16 个岛全枚举约 1.1 万个岛群；岛数越多只枚举越小的岛群），保证大盘面不会枚举爆炸。
5. **回溯兜底**：规则推不动时才搜索：优先选未知边最少的岛，按 `2 → 1 → 0` 尝试，并用上面四条规则剪枝。最后校验「每个岛桥数相等、无交叉、全连通」。

回放会按 `上下界 / 交叉封锁 / 连通必经 / 岛群割约束 / 回溯试探 / 补全` 标注每一步。上下界类步骤会写出具体的凑数依据，例如：

- 「上界凑满：需要 4 座桥的岛，候选边上限 1 + 1 + 2 = 4 → 每条边取最大（这条 1 座）」；
- 「下界凑满：需要 2 座桥的岛，候选边下限 1 + 0 + 1 = 2 → 每条边取最小（这条 1 座）」。

回放帧分两类，**按推理实际发生的顺序插入**：`推理`帧（只收窄候选边的取值范围、不落子，例如「这条边至少 1 座 / 至多 1 座」）和 `规则 1–4` 落子帧。所以 15×15 例题会先看到「数字 5 的岛其它候选边最多 4 座，这条边至少 1 座」，再看到「数字 2 的岛因此这条边至多 1 座」，最后才是「数字 4 的岛三条边上限 1+1+2=4，全部取最大」。不会跳过中间推导直接给结论。

同时，回放会把当前步骤涉及的候选边直接画在棋盘上，省得玩家在脑子里补「这条边其实已经至少 1 座」这种看不见的状态：

- **一条实线 + 一条虚线** = 至少 1 座、可能 2 座；
- **一条虚线** = 至多 1 座（也可能不架）；
- **极淡的点线** = 尚未确定（0–2 座）；
- 触发本步的岛会加一圈橙色虚线框；悬停在这些提示线上可以看到上下限的来源（例如「数字 2 的岛其它候选边已至少 1 座（数字 5 的岛其它候选边最多 4 座，还差 1 座 → 这条至少 1 座），再加 2 座会超过 2」）。

因此像「数字 4 的岛先填两条 1 桥、再补一条 2 桥」这类步骤，回放里既能看到前两条 1 桥为什么是确定值（它们的上限分别是 1、1，而岛所需桥数正好等于各边上限之和），也能在棋盘上直接看到「这条边至多 1 座」的虚线提示，不是把「至少 1 座」当成 1 座。导入的 15×15 例题可以被规则完整解出，回放中没有回溯步；内置 6 题里 5 题也能纯逻辑推满（`npm run check` 显示「逻辑可推满」），只有「初识搭桥」规则推不满，需要回溯兜底（唯一解检查从 22 个节点降到 4 个）。

## 功能

- **题库**：内置多道题，题目均校验唯一解
- **自定义题目**：2×2–120×120，点格子 / 文本行 / 图片三种输入，支持编辑和删除，保存不要求唯一解
- **图片导入**：从截图自动识别岛的位置并填写数字，保存为自定义题
- **实时校验**：超额与违规位置即时高亮，尚未搭够只提示剩余岛数；桥数达标的岛自动变灰
- **悬停提示**：空地显示虚线呼吸的预连接，单线桥荧光呼吸，双线桥显示红色叉浮动提示
- **逻辑解题**：域上下界、交叉封锁、连通必经、岛群割约束优先推理，推不动才回溯；逐帧回放显示理由，按 `P` 暂停/继续
- **提示一格 / 显示解**：提示优先揭示所有解一致的格子，显示解直接填入可行答案
- **撤销/重做**：按手势分组，一次拖拽只需一步撤销
- **进度保存**：自动保存当前题目进度，刷新不丢失
- **音效特效**：Web Audio 合成拨弦、水滴与落子动画，无外部音频资源
- **缩放/平移**：滚轮缩放，中键或 `Shift` 拖拽平移

## 技术栈

- Vite + TypeScript
- 原生 SVG（无框架）
- Web Audio 合成音效（无外部资源）
- localStorage / 项目内 `data/` 存储进度与题库

## 项目结构

```
src/
  main.ts
  core/
    app.ts / ui.ts / view.ts      界面、交互、缩放、回放控制
    store.ts / library.ts         题库、进度、上次题目存储
    audio.ts / fx.ts              音效与落子特效
  game/
    adapter.ts                    游戏规则接入
    image-import.ts               图片识别导入
    rules.ts                      推理规则
    logic.ts                      逻辑解题回放
    render.ts / state.ts          SVG 渲染与盘面状态
    validate.ts / solver.ts       实时校验与回溯求解
    puzzles.ts / puzzles-data.ts  题库加载与静态题库
```

## 命令

```bash
npm run dev       # 开发服务
npm start         # 开发服务 + 自动打开浏览器
npm run build     # tsc --noEmit + vite build
npm run gen       # 重新生成题库
npm run check     # 审计题库
npm run verify    # 参考解、逻辑回放与交互验证
npm run import-image  # 图片识别导入（预览 / --append / --verify / --map）
npm run audit     # 逐题审计逻辑解题
```
